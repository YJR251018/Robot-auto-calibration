# Eye-in-Hand 坐标系约定

## 基本规则

- 坐标系均为右手系；旋转矩阵属于 SO(3)，齐次变换属于 SE(3)。
- 使用列向量。`T_A_B`（数学记号 `⁽ᴬ⁾T_B`）将 **B 系坐标变为 A 系坐标**。
- `p_A = R_A_B @ p_B + t_A_B`；齐次形式 `[p_A;1] = T_A_B @ [p_B;1]`。
- `t_A_B` 是 B 系原点在 A 系中的坐标。长度全部为 **米**，内部角度为 **弧度**。
- 角度输入仅在显式 `degrees=True` 时使用度；毫米必须在导入边界除以 1000。
- 代码中的点集 `(N,3)` 按行存储，每行一个点，不改变列向量数学约定。

## 四个坐标系

| 符号 | 含义 | 本阶段状态 |
| --- | --- | --- |
| B | 机器人基座 | 固定参考系，无真实机器人 |
| E | 末端/法兰参考系 | 各采样时刻变化；未来须明确是法兰还是工具 TCP |
| C | 相机光学坐标系 | 固定在 E 上；采用 x 右、y 下、z 向前的视觉约定 |
| T | 标定板坐标系 | 相对 B 固定；未来明确原点和角点编号 |

视觉约定的 x 右、y 下、z 前依然是右手系。未来机器人轴向以实际设备文档为准，不擅自假定与光学轴一致。
数学示意：

```text
点 p_T --T_C_T,i--> p_C --X=T_E_C--> p_E --G_i=T_B_E,i--> p_B
```

## 固定板约束与 AX=XB 推导

定义：`G_i = T_B_E,i`，`Q_i = T_C_T,i`，待求 `X = T_E_C`，固定但可未知的 `Y = T_B_T`。

```text
G_i X Q_i = Y
G_i X Q_i = G_j X Q_j
inv(G_j) G_i X = X Q_j inv(Q_i)
A_ij = inv(G_j) G_i
B_ij = Q_j inv(Q_i)
A_ij X = X B_ij
```

这里 `B_ij` 是相对运动矩阵的名称，不是基座坐标系 B。相对运动次序一旦改变，A 与 B 必须成对重新推导，不能独立颠倒。
合成无噪声观测时，应使用 `Q_i = inv(X) inv(G_i) Y`；先检查每帧闭环等于 Y，再谈求解精度。

## 常见错误

1. 只对 R 转置，却把 t 直接取负。正确逆平移是 `-R.T @ t`。
2. `T_A_B @ T_C_B` 的中间坐标系不匹配。合法链应为 `T_A_B @ T_B_C`。
3. 混合米和毫米，或把度传入默认弧度接口。
4. 把 PnP 返回的板到相机方向当成相机到板。
5. 混用欧拉角内禀/外禀顺序。基础库仅提供单轴创建，多轴用明确的矩阵乘法。

矩阵数值本身不带坐标系和单位标签；有效性检查无法识别“数值合法但方向/单位错误”。
