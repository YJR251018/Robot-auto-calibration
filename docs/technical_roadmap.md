# 项目技术路线

## 阶段与交付门槛

| 阶段 | 工作 | 进入下一阶段的证据 | 当前状态 |
| --- | --- | --- | --- |
| 0 基础设施 | 虚拟环境、坐标库、测试、中文文档 | 测试通过、示例可运行、坐标约定明确 | 本轮完成 |
| 1 真值位姿仿真 | 生成 G_i/Q_i、调用现成求解器、真值误差 | 闭环与已知真值验证通过 | 方案完成，代码待做 |
| 2 误差与退化 | 旋转/平移噪声、样本量、轴覆盖 | 多随机种子、失败计数与误差分布 | 待做 |
| 3 投影与质量 | 固定内参、板角点投影、视野筛选，再加入图像噪声 | 可见性规则可单独验证，误差来源可区分 | 待做 |
| 4 主动采样 | 固定预算下比较候选选择与补采 | 共用候选池、消融、留出点验证 | 待做 |
| 5 硬件验证 | 获准后独立安排实际采集 | 真实配对数据、单位核对、现场许可 | 不属今晚范围 |

先做位姿级仿真，把 PnP 和内参误差排除；随后再做像素级仿真，避免一开始把多种错误混在一起。求解优先使用 OpenCV 现有实现，基础正确后才考虑自写求解器。

## 数据流与可复算要求

```text
配置+随机种子 → 真值 X/Y/G → 构造 Q → 闭环验证
 → 独立噪声注入 → 采样策略 → 固定求解器
 → 真值/留出误差 → 失败记录与分布统计 → 保存报告
```

建议未来每次实验记录：run_id、配置版本、seed、帧编号、G_i、Q_i、单位、噪声侧与乘法方向、候选编号、拒收原因、求解器、原始输出、异常、误差和运行耗时。先用 JSON/NPZ 等简单文件，暂不引入数据库。
在明确输入输出前不实现机器人正逆运动学，也不把自由 SE(3) 采样称为“机器人可达位姿”。

## 与申报对照的关系

无硬件阶段可比较随机、固定几何顺序、旋转覆盖和可见性加覆盖；随机策略只是仿真基线，不能写成真实“手动采集”。申报中的人工、固定轨迹、筛选加补采实机对照留到后续有设备时执行。

## 当前范围与代码组织

`src/handeye/transforms.py` 只负责坐标计算；测试不混入设备调用。后续按需要增加 `simulation.py`、`calibration.py`、`sampling.py`，每增加一项先建立独立输入输出约定和测试，不提前堆空模块。
