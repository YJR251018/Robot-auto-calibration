# M2 学习指南：怎样公平比较采样策略

## 1. 从“标定能算出来”到“哪些姿态值得采”

M1 已解决已知真值的仿真、求解与误差计算。M2 问的是：候选机器人姿态相同、可采样数量相同，选择顺序会不会影响估计？代码比较 ordered、random、rotation_farthest。最后一个优先选旋转姿态分散的候选，但它不是最优性保证；只有实验能说明当前场景的实际表现。

## 2. 三个必须分开的角色

生成器知道真实 X=T_G_C 和固定板 Y=T_B_T，用 Q=(G X)^-1 Y 合成观测。选择器只收到计划 G 和 ID。求解器只收到所选的 G/Q 与方法名。评价器在求解结束后才使用真值。

就像做题：出题者知道答案，答题者不能看到答案，阅卷者再对答案。把 SimulationData 整个传给选择器容易意外泄漏信息，所以接口刻意保持狭窄。

## 3. 独立留出到底独立在哪里

每个 repeat 用一个随机流生成 60 帧候选，另一个随机流生成 20 帧留出。两者共享安装与固定板真值，却不是同一序列的训练前缀/后缀。留出帧不能参与选择、求解或调阈值。

使用理想留出观测是为了隔离估计 X 的误差。若留出也加入噪声，测到的将同时包含部署观测噪声，属于另一个问题。留出帧与五个板点不是 100 个独立重复，因为它们共享同一个估计 X。

## 4. 误差为什么要看板上的点

手眼旋转误差的单位是度，平移误差是毫米，两者不能直接相加。旋转误差还会随点到旋转中心的距离转换成不同的位置误差。

对板点 p_T：

```text
估计点 = G_hold X_hat Q_hold p_T
真实点 = Y p_T
点距离 = ||估计点 - 真实点||
point_RMSE = sqrt(mean(点距离²))
```

例如所有坐标变换均为单位阵，而估计平移错了 (0.003,0.004,0)m，则每个点距离恰为 0.005m=5mm。绕 z 转错 90°，原点仍不移动，但 (1,0,0)m 的位置误差是 √2m。测试使用这类手算答案检验评价代码。

## 5. 公平对照的四个共同条件

1. 共用候选池和初始 ID `[0,1,2,3]`；初始样本也占预算。
2. 每个策略先生成到 N=20 的序列，N=8/12 取同一序列前缀，不重新抽样。
3. 每个候选 ID 有预先生成的标准噪声；选中相同 ID 就收到相同噪声。不能按照选择顺序新抽噪声。
4. 共用场景、求解器、留出集和预先固定的种子清单。发生失败也保留，不换到更好看的种子。

rotation_farthest 的分数是新姿态到已选姿态的最小 SO(3) 主角度，取分数最大者。差值≤1e-12 rad 视为数值并列，按最小 ID 决定。平移不参与这个简单策略，所以它可能忽略有价值的空间覆盖。

## 6. 如何读统计和图

正式协议每组 30 个 repeat。mean±sample SD 描述重复结果的离散程度，不是均值的置信区间。比较 farthest 与 random 时逐 repeat 相减；负值表示 farthest 的留出点误差更小。bootstrap 只重采样这些 repeat 的差值，不能把 20 帧×5 点当成更多重复。

误差统计条件于成功，必须同时看失败率。两策略只有共同成功的 repeat 才能形成差值，报告会列出配对数。若某策略误差低但失败更多，不能只凭均值判优。初步结果只约束当前配置，不能证明实机精度或创新性。

## 8. 如何实际运行

在 PowerShell 项目根目录中：

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
$env:PYTHONIOENCODING='utf8'
$env:MPLCONFIGDIR="$PWD\.venv\matplotlib-cache"
.\.venv\Scripts\python.exe -W error -m pytest -q -p no:cacheprovider --basetemp=.venv\my-M2-test-temp
.\.venv\Scripts\python.exe scripts\run_m2.py --config configs\m2_smoke.json --output experiments\M2_my_smoke
.\.venv\Scripts\python.exe scripts\verify_m2.py --run experiments\M2_my_smoke --report reports\M2_my_verification.json
```

运行目录、核验报告必须不存在，重跑时换新名字。pytest 的 basetemp 只用于本次测试，不填真实数据目录。正式实验将 config 换成 m2_sampling_v0_1.json。恢复同一目录的部分运行尚未实现；中断后保留旧目录，并核对状态后在新目录重跑，不能混合不同代码版本。

配置/种子/代码指纹与逐次结果一同保存。核验报告放在实验目录之外，因为产物哈希清单应保持固定。需要跨进程比较时加 `--compare experiments\另一个同配置运行目录`。

## 9. 理解题与答案

1. **为什么 30 个 repeat 各 100 个留出点，不能说有 3000 次独立标定？** 每个 repeat 只求得一个 X，内部点误差相关，独立重复数仍为 30。
2. **为什么不能用真实 X 算每个候选的预期精度，再让策略选择？** 那会将只有仿真评价器知道的答案泄漏给策略，不能代表未知安装下的实际选择能力。
3. **N=8 和 N=20 为什么要用同一选择序列？** 控制样本来源，较小集合是较大集合的前缀，可以观察增加样本的配对变化。
4. **覆盖分数增加但标定误差变大是否一定是 Bug？** 不是；覆盖分数是启发式代理，噪声和几何都会影响最终误差，应先查计算与公平性，再保留负结果。
5. **怎样正确研究机器人位姿测量噪声？** 用真实 G 生成 Q，再给测量 G 加独立噪声；若用带噪 G 重生成 Q，会人为恢复闭环并抵消要研究的误差。

当前 M2 是位姿级仿真，不能保证板可见、姿态可达或运动无碰撞；像素/PnP 研究是后续独立阶段。
